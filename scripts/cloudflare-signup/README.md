# Cloudflare signup

One Cloudflare account per run: a catch-all mailbox from **mailhub**, a proxy
from the **proxy generator** (or a stored one), a **Camoufox** profile in Owl,
and the sign-up form driven over WebDriver BiDi. It fills the form, ticks
Turnstile, submits, waits for the verification mail and opens its link.

Everything runs through the local Octo-compatible API (`127.0.0.1:58888`), so
the app must be running and the proxy has to exist (or be generated) before the
profile launches.

## Usage

```bash
# a stored proxy from the app
node scripts/cloudflare-signup/signup.mjs --proxy-uuid <uuid>

# a proxy generated by proxygen for this account (the bot's /keys pair)
export PROXYGEN_KEY=pgk_…
export PROXYGEN_SECRET=…
node scripts/cloudflare-signup/signup.mjs --country de --ttl-minutes 120

# a proxy line you already have
node scripts/cloudflare-signup/signup.mjs --proxy 'socks5://user:pass@host:1080'

# a specific mailbox, and a window the operator can click in
node scripts/cloudflare-signup/signup.mjs --email me@buildlog.vip --proxy-uuid <uuid> --manual
```

`MAILHUB_KEY` and `MAILHUB_SECRET` are required (the bot's `/keys`). The
generator pair is optional unless a proxy is generated.

## Flags

| Flag                         | Meaning                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `--proxy-uuid`               | use a proxy already stored in Owl                                                     |
| `--proxy`                    | add `[scheme://][user:pass@]host:port` to Owl and use it                              |
| `--country`, `--ttl-minutes` | what to ask proxygen for                                                              |
| `--domain`                   | mailhub domain; default: the first one accepting mail                                 |
| `--email`                    | use (or create) this address instead of a random one                                  |
| `--password`                 | fixed password; default: random, satisfies Cloudflare's rules                         |
| `--os`                       | fingerprint OS for the profile, default `mac`                                         |
| `--headed`                   | show the browser                                                                      |
| `--manual`                   | after the automatic attempts, wait for a human to tick Turnstile (implies `--headed`) |
| `--turnstile-timeout`        | seconds for the automatic Turnstile attempt, default 120                              |
| `--email-timeout`            | seconds to wait for the verification mail, default 180                                |
| `--no-token`                 | stop after the account is verified; skip login/API credentials                        |
| `--token-only`               | skip the signup: sign in with `--email`/`--password` and only create the credentials  |
| `--keep`                     | keep the profile and browser after the run                                            |
| `--report`                   | report path; default `scripts/cloudflare-signup/reports/<time>/report.json`           |

Env: `MAILHUB_KEY`, `MAILHUB_SECRET`, `MAILHUB_BASE`, `PROXYGEN_KEY`,
`PROXYGEN_SECRET`, `PROXYGEN_BASE`, `OWL_BASE`.

## Login and API credentials

1. **Verify in the signup session.** After the sign-up submit the browser is
   already inside the account; the run opens the account home, clicks
   **Resend verification email**, opens the new link in that same session and
   checks that the "Verify your email address" banner is gone. No sign-in and
   no two-factor step are needed for a fresh account.
2. **Sign-in** (for an account the run did not just create): email + password,
   then Cloudflare asks for a **7-digit code by email** on a new address. The
   field is a single input; the code is single-use, so every attempt needs a
   fresh one (mailhub `codes`), and a code is only sent once the address itself
   is verified.
3. **`/profile/api-keys`** → View → the account password → Verify → the key
   dialog. It holds a **visible Turnstile checkbox**: a ~404×71 widget between
   the text and the footer; the ~436×60 footer is Cancel | View. The checkbox
   is clicked at `(x + 19, y + 32)`, the dialog's View at `700 < x < 1000` and
   `y > 200`.
4. The key is now **`cfk_…`** (not the old 37-hex string) and is accepted as
   `X-Auth-Key` with `X-Auth-Email`.
5. With it the script creates a user API token (`POST /user/tokens`): every
   account and zone permission group on every resource. The API allows at most
   **300 permission groups per policy**, so the groups are split into one policy
   per resource scope (account, account.zone) and 300-group chunks — 410 groups
   become three policies.

Report fields: `apiKey`, `apiToken`, `apiTokenId`, `apiTokenPermissions`,
`accountId`, and `tokenError` when a step failed.

**Status:** the whole chain is confirmed on a live account
(`qmembc287@buildlog.vip`): signup → in-session verification → sign-in with a
2FA code → global key `cfk_…` → API token with 410 permission groups, verified
with `/user/tokens/verify`, `/accounts` and `/zones`. Exits matter: `Hi_4`
solved the sign-up Turnstile in ~14 s while dataimpulse and the static exit
hung, and a proxy generated by proxygen came out of the same dataimpulse pool.

## What a run leaves behind

`scripts/cloudflare-signup/reports/<time>/report.json` — the address, the
password, the proxy, the profile, per-step timings, the verification link and
the outcome (`created-verified`, `created-unverified` or `failed`). The reports
directory is gitignored; treat it as the account store. Screenshots of a failed
step land next to it.

Exit code is `0` for a verified account, `1` for a failure, `2` when the account
was created but a later step (mail or verification) did not finish.

## How it works

1. `POST /api/v1/mailboxes` on mailhub (signed v2 HMAC, shared with proxygen).
2. Proxy: stored, added via `/api/v2/automation/proxies`, or generated with
   `POST /api/v1/proxies` on proxygen.
3. `POST /api/v2/automation/profiles` with `browser: "camoufox"` and the proxy,
   then `POST /api/profiles/start` with `debug_port` — the answer carries the
   BiDi `ws_endpoint`.
4. `session.new`, `browsingContext.setViewport` (1280×1000, so the whole form
   fits), then the form: email and password typed as trusted key events, each
   value read back and retyped if React hydration swallowed it.
5. Turnstile: the widget box is the lowest ~70 px box between the password
   field and the submit button. Its challenge may resolve without a click; if
   not, the checkbox is clicked at a small fixed offset inside the box
   (`+22, +34` and neighbours). The widget sits in a closed shadow root, so it
   cannot be addressed as an element.
6. `button[type=submit]`, then the mail: `GET /mailboxes/:address/messages` →
   the first Cloudflare link → opened in the same profile.

## Measured on one account (2026-11-24, macOS, dataimpulse SOCKS5)

| Step                                      | Time       |
| ----------------------------------------- | ---------- |
| mailbox                                   | 0.8 s      |
| profile                                   | 5.0 s      |
| launch (first launch clones Camoufox.app) | 32.8 s     |
| form (edge challenge + fill)              | 23.9 s     |
| Turnstile token                           | 28.2 s     |
| submit → dashboard                        | 12.8 s     |
| verification mail                         | 0.7 s      |
| verification link → login page            | 6.6 s      |
| **total**                                 | **~2 min** |

Turnstile is the flaky step: of five attempts that reached the form, one
produced a token in 28 s; the others sat on `Checking your Browser…` or
`Verificando…` until the timeout. The checkbox click lands (the widget turns to
"verifying"), but Cloudflare's verification sometimes never answers on a given
exit. Retry with another proxy before assuming the script broke; `--manual` with
a visible window is the fallback.
